# Qlibworks 因子开发与管线组织方案

> 依据：项目内 `scripts/evaluation/run_eval.py`（深评+准入一体，2026-10-12 admit 合并）、`scripts/training/{factor_screen,select_factors,select_momentum_price,screen_factors,train_tree-doubao}.py`、`src/qlworks/evaluation/*`、`factor_data/factor_library` 实际代码与注释（P0-1 单一准入通道 / P1-6 候选池=训练因子池 / P2-整合白名单）。
> 对标范式：世界一流机构"因子分类筛选 → 有效因子进候选池 → 跨类别组合成实盘因子 → 选股"。

---

## 1. 核心结论

项目**不需要再发明新流程**——代码注释里已经设计好了收敛方案，只是脚本散落、闭环未跑通。按下面六个阶段组织，每阶段只保留**一个唯一入口**：

| 阶段 | 唯一入口 | 输入 | 输出 | 运行频率 |
|---|---|---|---|---|
| 0 因子新建 | `factor_library/*.yaml`（5+1 家族） | 因子表达式（qlib+duckdb） | 家族 YAML 登记 | 随时 |
| 1 因子计算 | `scripts/evaluation/batch_compute.py` | 家族 YAML + ClickHouse/Qlib | `factor_data/warehouse/`（因子值） | 首建全量、每周 `--append` 增量 |
| 2 分类筛选 | `scripts/training/factor_screen.py` | warehouse 因子值 | `family_candidates_{ts}.json`（按家族+配额校验） | 月度 |
| 3 单因子深评 | `scripts/evaluation/run_eval.py` | warehouse + 阶段 2 名单（`--factor-list`） | `qualified_factors/{core,satellite,archive}/` | 月度 |
| 3+4 单因子深评+准入 | `scripts/evaluation/run_eval.py --admit` | warehouse + 阶段 2 名单（`--factor-list`） | `qualified_factors/{core,satellite,archive}/` + `registry/candidate_pool.json`（Alpha Book v2） | 月度 |
| 5 实盘因子构建 | `scripts/training/train_tree-doubao.py` | 候选池 admitted 名单 | 训练模型 → 实盘选股 | 周频（与调仓对齐） |

**关键纪律**：
- 候选池**唯一写入通道**是 `run_eval.py --admit` 三关检验（相关 ≤0.70 / 增量 ICIR 边际贡献 / 近 3 年方向一致；2026-10-12 admit 已合并进 run_eval，评测即入库）；任何其他脚本不得直接写 `candidate_pool.json` 的 `factors` 区（精选脚本只允许写 `suggestions` 建议区，状态 `suggested`）。
- 训练端只消费 `status=admitted` 的因子（`train_tree-doubao.py` 的 `preselected_factors_file` 已指向候选池），保证"筛选端与训练端口径一致"。

## 2. 多套筛选脚本的定位与处置（消除困惑）

现有筛选脚本不是平行替代，而是**同一"分类筛选"阶段的历史演进产物**：

| 脚本 | 职责 | 现状 | 处置 |
|---|---|---|---|
| `screen_factors.py` | 5 道快检门粗筛（质量/IC/稳定/冗余/BH） | 实现已被 factor_screen 复用 | 冻结，研究期回看 |
| `select_factors.py` | 通用类别内精选（嵌入式特征选择、跨窗口置换检验） | 实现已被 factor_screen 复用 | 冻结 |
| `select_momentum_price.py` | 量价家族专用精选（BH-FDR 置换、IC 衰减硬门槛、方向门控） | 差异化检验应并入 `FAMILY_DEFS["momentum_price"]`（crowding 已有，补 FDR/衰减门控） | 冻结留档，参数并入统一引擎 |
| `factor_screen.py` | **统一筛选引擎**：FAMILY_DEFS 家族配置驱动差异化质检 | 已是收敛目标 | **保留为阶段 2 唯一入口** |
| `run_eval.py` | 单因子深评分档 + **`--admit` 三关准入建池（评测即入库，2026-10-12 admit 合并）** | 阶段 3+4 入口 | **保留（唯一入口）** |

> `run_eval.py --admit` 不是与 `select_momentum_price.py` 平行的"另一套筛选"，而是管线的**下游阶段**（深评 → 准入一体化，对齐 WW BRAIN 模拟器→提交校验范式）。`factor_screen.py`（分类筛选）→ `run_eval.py --admit`（深评+准入建池）是严格上下游。

### 白名单与建池的先后关系（避免循环依赖）
- `select_factors.py / select_momentum_price.py` 的 `pool_whitelist` 设计用于**池已存在后的增量精选**（只评估 admitted）。
- **第一轮建池**：候选池不存在 → 白名单自动回退全库（代码已处理）→ 筛选 → 深评 → 三关准入建池。
- **后续轮**：新因子入 YAML → 计算 → 分类筛选 → 深评 → 增量准入并入池；旧池不再每次全量重筛。

## 4. 落地步骤（可直接复制）

### 4.1 先合并差异化检验到统一引擎（一次性）
将 `select_momentum_price.py` 的动量家族专属检验（BH-FDR 置换、IC 衰减硬门槛、H1/H3/H5 方向同号门控）补入 `factor_screen.py` 的 `FAMILY_DEFS["momentum_price"]`（现有 `crowding: True` 保留）。

### 4.2 首次闭环（建池）
```powershell
# ① 分类筛选（全家族，或先量价家族试跑）
python scripts/training/factor_screen.py --all
#   或单家族： python scripts/training/factor_screen.py --family momentum_price

# ② 对 family_candidates_{ts}.json 名单做深评 + 三关准入（--admit 评测即入库，2026-10-12 起替代 admit_to_multifactor.py）
python scripts/evaluation/run_eval.py --factor-list <family_candidates_{ts}.json 中名单文件> --admit

# ③ 首次建池 = ② 自动完成（candidate_pool.json 由 --admit 三关写入）；存量补录用 --admit-only
python scripts/evaluation/run_eval.py --admit-only

# ④ 训练端读取候选池（preselected_factors_file 已指向 candidate_pool.json）
python scripts/training/train_tree-doubao.py
```

### 4.3 常规运行节奏
```text
每周：  batch_compute.py --all --append        （增量计算）
月度：  factor_screen.py --all → run_eval.py --factor-list ... --admit
周频：  train_tree-doubao.py                    （训练/调仓对齐）
```

### 4.4 脚本治理
- 冻结：`screen_factors.py`、`select_factors.py`、`select_momentum_price.py`（功能已并入 `factor_screen.py`）。
- 删除/归档：`scripts/training/select_factors - 副本.py`。
- 新因子纪律：无 warehouse 缓存的因子先入 `other_factors.yaml` → 计算缓存 → 按 category 归档至家族 → 参与下一轮筛选。

## 5. 运行频率依据（机构"慢决策/快决策"分层）

| 决策 | 频率 | 依据 |
|---|---|---|
| 分类筛选 → 候选池刷新 | 月度（季度更稳） | ~2 年窗口每周仅增约 1% 信息，高频刷新在硬门槛附近引发候选池抖动，拖累下游特征稳定性 |
| 窗口前滚 | 每次重跑整体前滚一个月（互不重叠窗口） | 保持近端数据新鲜 + 避免重叠样本 |
| 模型训练/选股打分 | 周频 | 与调仓对齐 |

## 6. 追加建议（来自项目已有审查）

- `factor_screen.py` 输出 `family_candidates_{ts}.json` 已含配额校验结论，建议在 `run_eval.py --admit` 准入后增加**家族配额回写**（量价 ≤35% 红线），让候选池直接携带配额状态。
- risk 家族仅作风险约束，不参与 Alpha 比拼，准入时按 `FAMILY_DEFS["risk"]`（不强制 IC）处理。
- 建议在 `candidate_pool.json` 生成后补充 CI 校验：任何脚本对 `factors` 区的写入必须经由 `CandidatePool` 类（`src/qlworks/evaluation/candidate_pool.py`），防止旁路。
